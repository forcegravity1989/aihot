# 洞察：AIHOT 这两周为什么冒出这么多新问题

2026-10-10 · 对应 issue [#54](https://github.com/forcegravity1989/aihot/issues/54) · 证据来自上游仓库的 issue/PR/提交记录、线上站更新日志、我们自己的采集日志，以及把上游代码在本机跑一遍的结果。

## 一句话

AIHOT 在 20 天里做了两次整体重写（9 月 8 日、9 月 28 日），第二次是让 Claude 从头生成约 4 万行 TypeScript 并当天开源；随后每天叠一个大功能，再每隔两三天把私有生产仓的改动整包同步到开源仓。问题不是代码质量突然变差，而是**变更速度远超验证速度**，而且变更的是公共接口（分类名、域名、API 版本）。我们作为下游消费者，首先吃到的就是这些接口变化。

## 时间线（上游公开信息）

| 日期 | 事件 | 后果 |

6 天里 50 个提交，其中 3 个是上述整包同步；维护者一人 68 个提交，其余十来位社区贡献者合计 30 个左右。

## 问题长什么样（25 个 issue、60 个 PR 归类）

共同点：都不是设计错，而是**重写后没有在真实数据和多样环境上回放过**。上游 AGENTS.md 自己也写了评审最常退回的原因：「测试只证明你想到的情况」。

## 根因

1. **两次整体重写，AI 生成的大体量代码。** 4 万行一次成型，边界情况靠社区在生产里撞出来。上游 issue 回复快（多数当天关闭），但这恰恰说明 bug 存量大。
2. **功能日更叠在刚重写的系统上。** 模型榜算法两周改了两次，分类、精选规则、移动端、主题页都在动。每一次都改到读者和下游看得见的东西。
3. **开源仓不是开发现场。** 私有生产仓才是；开源仓靠整包同步跟进，历史又被重置过一次。社区 PR 合进去后，下一次同步再「对齐上游写法」重做一遍（PR 126 → 提交 cc7297c 就是一例）。fork 它的人每周都要面对几十个文件的合并。
4. **规模突然放大。** 12 天 1700 个 fork，Windows、本地模型、600 个信源的站都在跑，暴露了作者单一环境下的全部假设。
5. **单人维护。** 68/100 的提交出自一人，评审靠给贡献者的 Agent 写规则。响应快、吞吐高，但 churn 同样高。

## 对千里眼的直接影响（已观测到的）

- **10-08 当天 aihot 采到 0 条**：`aihot.virxact.com` DNS 解析失败（日志 `NameResolutionError`）。旧域名 10-31 后失效，`config/sources.yaml` 的 `base_url` 必须切到 `aihot.news`。
- **分类名拆分**：线上 `feed/all.xml` 现在给的是「教程」「观点」，我们的 `category_map` 只认「技巧观点」。10-09 的 141 条里已有 4 条空类别，之后每天约 30 条会落空，直接影响日报分栏。
- **信源构成变了**：近 50 条全量 feed 里 IT之家 12 条、X 账号（Rohan Paul 7、Ethan Mollick 3）、公众号若干。口味往「媒体 + X」偏，一手官方占比下降。我们的日报若主要吃这个源，味道会跟着变。
- **在本机跑上游**：Node 26（上游要求 ≥ 24.11）下 `typecheck` 通过；`test:standalone` 181 个里 2 个代理相关用例在**未改动的上游 main** 上也挂，是这台机器的环境问题；web 测试要 Playwright 浏览器；完整测试要 PostgreSQL；三个常驻进程对 8G 内存不轻松。
- 顺带发现：我们自己的 `company` 后端每天 `FAIL`（与 AIHOT 无关，另开 issue 处理）。

## 结论

**现在不要 fork 整个引擎上线。** 目标在动：开源仓接口版本 4.0.0、线上站 2.0.0、分类名刚拆、域名在迁、每两三天一次几十个文件的同步。fork 等于给自己背一份别人正在重写的代码。

**建议的姿态：**

1. **继续做消费者，但只吃它承诺稳定的那一层。** `aihot.news` 的 `/api/v1` 与 RSS 是上游明确承诺「地址与格式不变」的公开接口；我们读它，不碰它的引擎。立刻要做：切域名、补「教程」「观点」两类映射。
2. **infra 内容自己采。** 上游的运营信源名单不公开，它的口味也不以 infra 为重。今天在 fork 工作副本里整理并实测可达的 36 个信源（vLLM / PyTorch / NVIDIA Dev / Together / Modular / Thinking Machines 博客，7 个 GitHub Releases，Tri Dao / SemiAnalysis / Interconnects 等，arXiv cs.DC）可以直接回灌到我们的 `config/sources.yaml`，不依赖上游。
3. **借它的口味资产，不借它的引擎。** `industry/prompts/` 的评分、理解、结构化提示词和门槛是公开的；我们日报的提炼提示词可以参考它的写法。这部分改动在 `~/projects/qianliyan-hot` 本地分支里，留着参考，不推、不部署。
4. **一个月后再看。** 观察三件事：开源仓 open issue 数与「同步引擎修复」提交的体量是否收敛；接口版本是否一个月没动；分类与域名是否稳定。11 月中旬再评估要不要 fork。
