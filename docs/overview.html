01定位与四条铁律

为什么存在 · 价值主张

AI 领域的高价值信息散落在 REST/RSS、GitHub、官方 blog、YouTube 演讲、播客、X 动态、GitHub trending、系统提示词与 changelog 等异构渠道。千里眼并行巡视这些渠道，在本地熔成一份统一池，再切成频道页、热榜、深读/浅读日报、HTTP API。

设计哲学四条铁律 ① 以本地数据为准，不凭记忆　② 每条必带 URL　③ 简体中文 + 人话　④ 交叉验证是核心价值——v0.3 升级为「叙事 vs 实证是否吻合」。

04变更情报 · 王牌

交叉验证的最高形态：叙事（演讲/博客的说法）与实证（真实 diff）是否吻合

三个真实变更源被沉淀为结构化变更流：Piebald 的系统提示词 CHANGELOG（按 Claude Code 版本记录、每版带 token 增减、NEW/REMOVED 分类、链 commit）、anthropics 官方插件市场 + bump 追踪、zhoux77899 的插件/skill 日榜（只取 7KB 日更，绝不碰 31MB/75MB 的巨型 json）。

叙事 ↔ 实证 映射

🗣️ 叙事（talk / blog）

"Fable 5 减少了 80% 提示词"

🔬方向 · 量级
比对

📐 实证（changelog）

同主题版本 token_delta
聚合 = 大幅负值

pipeline/change_intel.py 对含数字断言（\d+% / \dx / \d+倍）的叙事类 item 抽断言 → 找同主题的实证类变更 item → 比对方向与量级，写 extra.corroboration = {claim, evidence, verdict}：

🔬 实证 corroborated　方向吻合且量级达阈值
存疑 unverified　找不到实证
矛盾 contradicted　方向相反

为什么这是护城河 别处的 AI 简报止于"谁说了什么"。千里眼能回答"他说的，被真实的代码/提示词 diff 证实了吗"——把一句演讲金句，钉在可溯源的 commit 上。LLM 判定可选、regex 回退兜底，永不阻塞。

另外两件事

  • 绑定：同版本/主题的提示词变更与插件 bump 绑成一条"版本变更卡"（时间线）。
  • 业界资产演进：从 trending 日榜发现新入场/上升项目（multica、teams.ai、kanban.ai 这类），勾勒生态演进。

05交叉验证与核心算法

core/utils.py · 被单元测试锁死语义

签名去重：标题 NFKC 归一 → casefold → 去标点取前 50 字 → SHA1 前 16 位；release 类用 source|version 防误合并。交叉验证合并：同签名聚合，source_list 累积、cross_refs = 源数 − 1、取最高权重标题/最长摘要/最早日期——多源报道自动加成热度。

hotness = weight × 0.5^(age_days / 7) × (1 + 0.35 × ln(1 + cross_refs))
          └ 信源权威度   └ 新鲜度(半衰期7天)      └ 交叉验证加成

重磅校准：📈 重磅 cross_refs≥3；⚡ 一手速报 weight≥0.95 且 24h 内。个性化叠加 extra.personal_score = hotness × 兴趣乘数。

06人物画像 · 读者画像 · 历史

两种画像都要（用户确认）

人物画像（被追踪对象）

pipeline/persona.py 按 extra.handle 聚合 builder 类条目 → 每人一张档案：bio、头像、近期在关注…、活跃主题、top 动态、影响力数字（total_engagement / item_count）。LLM 增强 topics/recent_focus，规则回退。

读者画像（你自己）+ 历史

core/profile.py：reader.yaml 显式兴趣（tag/source/people 乘数）× 从 history.jsonl（seen/open/deepread/received）与 feedback.jsonl 按 recency 衰减派生的偏好 → personalize() 给信息流写 personal_score 与命中原因，驱动"为你推荐"版面。mute 命中归零。无配置时退化为 hotness。

07深读/浅读 + YouTube 字幕

浅读=看过标题即已接收；深读=全文重点研读，突出图片与论点

一份 digest-final.json 渲染两个视图 + 一个带切换的合并页：

  • 浅读（glance）：按 format 分组的极速标题流，每行 format 图标 + 交叉验证徽章 + 标题 + 来源 + 原文链接；「标记已读」localStorage 置灰。一眼扫完即"已接收"。
  • 深读（deep）：每条精读卡——video/talk 突出缩略图 + 演讲要点，repo 突出 star 增量，paper 突出摘要；distill 四段（要点/脉络/影响/局限）+ 关键论点 theses + 交叉验证展开 + 🔬 叙事↔实证 标记。
YouTube 字幕（按 baoyu 真实方法） engine/youtube_transcript.py 的 get_transcript 多级回退：① web-access CDP + baoyu 页内脚本（真实 Chrome/会话，读页面自带 API key 调 innertube 取字幕轨）② 配置代理 QLY_TRANSCRIPT_PROXY ③ 直连 best-effort ④ 回退视频描述。深读对 video/talk 把字幕全文喂 LLM 提炼论点——真正"读懂"大会演讲。纯 requests 从数据中心 IP 拿不到，正因为缺真实浏览器上下文。

08频道与 HTML 简报

16 个主题频道 · 单文件自包含

一条 item 可同属多频道，跨源按主题聚合。频道 match 支持 tags / keywords / formats / categories / sources / source_kinds（块内 AND、any_of 表 OR）。当前频道：headlines · models · claude-code · practices · talks · podcasts · trending · change-intel · papers · builders-live + 若干 legacy。

digest.html：自研极简模板引擎（不依赖 jinja2，编译节点树、禁 eval）；三排序按钮（🔥热度/🕒时间/📈得分）；Ctrl+K 命令面板跨版面模糊过滤；「为你推荐」与「人物画像」版面；大牛头像 base64 内嵌；每条带可点 URL。真实浏览器实测：performance.getEntriesByType('resource') 为空——零外链、单文件自包含。

10项目管理：AI-native SDLC + loop

docs/PLAYBOOK.md · 文档即合同，issue 即工作单元，wave 即并行实现

  1. Explore：侦察真实信源/约束，抓成 tests/fixtures/real/（对着真实结构写解析器）
  2. Plan：落 intent.md（成功标准）/ spec.md+spec-v0.3.md（唯一实现合同）/ plan.md
  3. Issues：GitHub Epic + 子任务（#7 变更情报 · #8 transcript · #9 信源 · #10 收尾 · #11 推送）
  4. Implement：拆 wave 派 Opus/Sonnet 子代理（不用 Fable），波内文件互斥杜绝冲突
  5. Verify：全量 pytest 绿 + 离线端到端冒烟（DoD）→ 关 issue → 勾 Epic → 下一个
外发动作红线 push / merge / 删数据永不自动放行，需逐次显式批准——故「首次推送 GitHub」独立成 issue #11、默认不执行。
